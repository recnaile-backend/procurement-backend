# Asset Service

Reusable-asset lifecycle service for the procurement and inventory platform.

## Production workflow

```text
Outward issues approved request
        |
        | OUTWARD_ISSUED event
        v
Asset Service
        |
        +-- reusable item -> create/assign asset
        |
        +-- non-reusable -> ignore
        |
        v
Return Service
        |
        | RETURN_RECORDED
        v
Asset Service -> close reusable asset assignment

Inventory Service owns stock quantity and stock deduction.
```

The Asset Service does **not** consume Inventory's `StockIssueApproved` command. Inventory consumes that command. Asset creation is driven by Outward's `OUTWARD_ISSUED` event, which contains the recipient, department, issuer and item-level `assetTracked` data required for assignment.

## Kafka contracts

- `outward.events` / `OUTWARD_ISSUED` -> Asset Service
- `return.recorded` / `RETURN_RECORDED` -> Asset Service
- `inventory.events` / `StockIssueApproved` -> Inventory Service, not Asset Service

For asset-tracked quantities greater than one, one asset record and assignment is created per reusable unit. Every asset uses the Outward number as `outwardNumber`. Multiple reusable units from the same outward therefore share the same outward number; `assetId` uniquely identifies the physical asset.

### Production ownership rules
- `assetId` is the unique Asset Service identifier, for example `ASSET%2F26-27%2F001`. The service upgrades the legacy unique `outwardNumber` index to a non-unique index when `ASSET_ENSURE_INDEXES=true`.
- `outwardNumber` is always the Outward number, for example `OUT%2F26-27%2F001`. It is intentionally non-unique because one outward can issue multiple reusable units.
- Normal asset creation and assignment are event-driven from `OUTWARD_ISSUED`; direct create/assign/return endpoints are ADMIN-only recovery operations.
- Normal returns are driven by Return Service `RETURN_RECORDED`; Asset Service does not own Inventory stock.
- Asset outbound Kafka messages use a transactional Mongo outbox with retry.
\n\n### Reference conventions\n\n- Asset IDs are server-generated in URL-encoded form such as `ASSET%2F26-27%2F001`.\n- `outwardNumber` is the Outward business reference, for example `OUT%2F26-27%2F001`.\n- `returnId` is owned and generated by Return Service using the platform financial-year convention, for example `RET%2F26-27%2F001`; Asset Service consumes that value and does not generate it.\n
