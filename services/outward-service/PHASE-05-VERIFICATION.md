# Master Data Validation Verification

## Scope

This version adds synchronous validation against the documented Master Data REST APIs.

## Checks

- Item existence and ACTIVE status.
- Requested quantity against current Master Data available stock.
- Department name existence and ACTIVE status.
- Optional project existence and ACTIVE status.
- Duplicate item IDs rejected.
- Asset tracking derived from Master Data, never accepted from the create request.
- Authorization, correlation ID and traceparent are propagated by the RestClient interceptor.
- Downstream calls use bounded connect/read timeouts.
- No direct Master Data MongoDB access.
- No inventory mutation or Kafka business event added.

## Outward number

The existing domain behavior remains unchanged. Generated values are stored exactly as:

`OUT%2F26-27%2F001`

No double-encoded `%252F` value is generated by this implementation.

## Local verification limitation

The isolated packaging environment does not contain the repository root Gradle wrapper or Gradle installation. Therefore the definitive multi-project Gradle test must be run from the user's repository root.
